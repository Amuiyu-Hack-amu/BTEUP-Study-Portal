Topic 1: Anatomy of an Android Application 🟢 BTEUP SYLLABUS

🔵 BASIC FOUNDATION

A. Introduction

  • What: Anatomy ka matlab "body ka structure". Android app ke andar kaun-kaun se parts hote hain aur wo kaise judte hain.
  • Why needed: Jab tak structure nahi samjhoge, app bana nahi paoge aur debugging mushkil hogi.
  • Where used: Har Android app (WhatsApp, YouTube, Maps) isi structure par bani hoti hai.

B. Definition (Normal English)

DefinitionThe anatomy of an Android application means its internal structure: the app components (Activity, Service, Broadcast Receiver, Content Provider), the resources, the source code and the AndroidManifest.xml file, which together make a working app.

C. Hinglish Explanation

HinglishAndroid app ek ghar jaisa hai. Ghar me kamre (Activity), kaam karne wala naukar (Service), doorbell (Broadcast Receiver) aur godown/store (Content Provider) hote hain. Ghar ka naksha (map) AndroidManifest.xml hai, jisme likha hota hai ki ghar me kya-kya hai.

D. Real-Life Examples

WhatsApp / YouTube / Camera
  • WhatsApp: Chat screen = Activity; background me message download = Service; naya message aane par alert = Broadcast Receiver; contacts ka data = Content Provider.
  • YouTube: Video screen = Activity; background audio / download = Service; internet connect/disconnect ki khabar = Receiver.
  • Phone dialer: Dial pad = Activity; incoming call detect = Receiver; contacts = Content Provider.
Behind the scenes: Jab app icon tap karte ho, Android app ka process banata hai, Manifest padhta hai, launcher Activity dhundhta hai aur uska onCreate() chalata hai.

Four Main Components 🟢

ComponentKaam (Purpose)Example
ActivityEk screen jo user ko dikhti haiLogin screen
ServiceBackground kaam, UI nahi hotaMusic player
Broadcast ReceiverSystem/app ke events sunnaBattery low, boot complete
Content ProviderData dusre apps ke saath share karnaContacts, Gallery

F. Important Points 🔴

  • Android app = components + resources + manifest + code.
  • Har component AndroidManifest.xml me declare hona zaroori hai (Broadcast Receiver dynamic ho to exception).
  • Components ek dusre se Intent ke through baat karte hain (Content Provider ContentResolver se).
  • Android app ko APK/AAB file me package kiya jata hai.

Simple Example App Structure (Code)

package com.example.myfirstapp;

import android.os.Bundle;
import android.widget.TextView;
import androidx.appcompat.app.AppCompatActivity;

public class MainActivity extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);          // 1
        setContentView(R.layout.activity_main);      // 2
        TextView tv = findViewById(R.id.tvHello);    // 3
        tv.setText("Hello BTEUP!");                  // 4
    }
}

Build Process (internal)

Java/Kotlin + XML + Resources→Compile (.class)→D8/R8 → DEX (.dex)→Package + Sign→APK / AAB
  • R class: Build ke time automatically banti hai; resource names ko integer IDs se jodti hai.
  • R8 code shrink + obfuscate karta hai (APK chhota aur secure).
  • Har app apne alag Linux process aur user ID me chalti hai (sandbox) – isi se security milti hai.
Common errors
  • Activity manifest me declare nahi ki → ActivityNotFoundException.
  • findViewById se null → galat layout ya ID.
  • Layout ya resource ka naam capital letters/space ke saath → build error (sirf small letters, numbers, underscore).
Best practiceHard-coded text ki jagah strings.xml use karo; naye projects me Kotlin + Jetpack recommended hai, par BTEUP me Java chalta hai.

Topic 3: Application Context 🟢 BTEUP SYLLABUS

🔵 BASIC FOUNDATION

A. Introduction

  • What: Context app ke "current situation" ki information hai – app kaun hai, kaun si resources/services use kar sakti hai.
  • Why needed: Toast dikhane, nayi Activity kholne, string/image lene, file/database access karne ke liye Context chahiye.
  • Where used: Almost har Android operation me (Toast, Intent, SharedPreferences, Adapter...).

B. Definition

DefinitionContext is an abstract class of the Android system. It gives information about the application environment and allows access to resources, system services, and app-level operations such as starting an Activity or showing a Toast.

C. Hinglish

HinglishContext ek "access card" jaisa hai. Office me card dikhao to gate khulta hai; waise hi Context dikhao to Android tumhe resources, Toast, Intent, services use karne deta hai.

D. Real-Life Examples

  • WhatsApp: "Message sent" Toast dikhane ke liye Context chahiye.
  • YouTube: Video list ki RecyclerView/Adapter ko layout inflate karne ke liye Context chahiye.
  • Camera app: Photo save karne ke liye app ki file directory Context se milti hai.

Two Main Types 🟢

F. Important Points 🔴

  • Activity, Service, Application – ye sab Context ke subclasses hain.
  • UI/Dialog ke liye Activity Context use karo.
  • Lambi life wale objects ke liye Application Context use karo.

Context Hierarchy

Uses of Context

  • Toast: Toast.makeText(context, "Hi", Toast.LENGTH_SHORT).show();
  • Intent: new Intent(context, SecondActivity.class)
  • Resources: context.getString(R.string.app_name), context.getResources()
  • System services: context.getSystemService(Context.VIBRATOR_SERVICE)
  • Files / preferences / database: getSharedPreferences(), openFileOutput()

Java Example

public class MainActivity extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        Context appCtx = getApplicationContext();                    // 1
        Toast.makeText(appCtx, "App Context Toast", Toast.LENGTH_SHORT).show(); // 2

        Intent i = new Intent(MainActivity.this, SecondActivity.class); // 3
        startActivity(i);                                            // 4

        String name = getString(R.string.app_name);                  // 5
    }
}
  1. Pure app ka Context (Application Context) liya.
  2. Toast bana kar dikhaya. Output: screen ke niche chhota message.
  3. MainActivity.this = Activity Context. Intent me "kahan se" (from) Context chahiye.
  4. Second Activity start ki.
  5. Resource (strings.xml) se text liya – ye Context ke through hi hota hai.

Common mistakes ⚠️

  • Dialog ke liye Application Context dena → BadTokenException.
  • Activity Context ko static variable me rakhna → memory leak.

🟡 ADVANCED KNOWLEDGE

Memory Leak Concept

Memory leakWhen an object is no longer needed but still referenced, so garbage collector cannot free it. Agar koi long-living object (static field / singleton) Activity ka reference pakad le, to Activity destroy hone ke baad bhi memory me rehti hai.
// ❌ Wrong – leak
public class Helper {
    static Context ctx;                    // static = app jitni lambi life
    static void init(Context c){ ctx = c; } // Activity pass hui to leak
}

// ✔ Right
static void init(Context c){ ctx = c.getApplicationContext(); }
  • Best practice: Singleton/long-life objects me hamesha getApplicationContext() store karo.
  • ContextWrapper: Context ko wrap karke behaviour badalne ke liye (decorator pattern); Activity, Service sab ContextWrapper ke bachhe hain.
  • Android 11+ (visual contexts): Application Context UI-related cheezein (jaise WindowManager) use kare to galat result/StrictMode warning aa sakti hai.
  • Modern approach: ViewModel me Context mat rakho; zarurat ho to AndroidViewModel + application context ya Hilt @ApplicationContext.
⚡ Quick Revision: Context = app environment ka access. Types: Application Context (getApplicationContext(), app-wide life) aur Activity Context (this, activity life). UI/Dialog = Activity; long-life object = Application. Static me Activity Context = memory leak.

Topic 4: Activities 🟢 BTEUP SYLLABUS

🔵 BASIC FOUNDATION

A. Introduction

  • What: Activity app ki ek screen hai jahan user kuch dekhta ya karta hai.
  • Why: User se baat karne (UI) ka yahi main tareeka hai. Bina Activity ke visible app nahi.
  • Where: Login screen, chat screen, camera preview, settings page.

B. Definition

DefinitionAn Activity is an Android component that provides a single screen with a user interface where users interact with the app. It is a subclass of Context (via ContextThemeWrapper), usually extends AppCompatActivity.

C. Hinglish

HinglishActivity = app ka ek page. WhatsApp me chat list ek Activity, chat window dusri Activity, settings teesri Activity. Ek app me bahut saari Activities ho sakti hain; ek launcher (main) Activity hoti hai jo pehle khulti hai.

D. Real-Life Examples

  • WhatsApp: Chat list → chat screen → profile screen (alag Activities).
  • YouTube: Home feed aur video-player screen.
  • Google Maps: Map screen, search screen, directions screen.

Real-Life Lifecycle Story

App kholna (create + visible) → Home button dabana (minimize = stop) → wapas aana (restart + resume) → Back dabake band karna (destroy). Android ye sab events par apne methods chalata hai – ise Activity Lifecycle kehte hain.

F. Important Points 🔴

  • Activity = 1 screen (UI).
  • Manifest me declare karna zaroori.
  • Lifecycle me 7 methods: onCreate, onStart, onResume, onPause, onStop, onRestart, onDestroy.
  • Activities ka stack banta hai – Back Stack (LIFO).

Creating, Registering and Starting Activities (Practical)

// SecondActivity.java
public class SecondActivity extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_second);
        String name = getIntent().getStringExtra("USER_NAME");   // data receive
        int age     = getIntent().getIntExtra("USER_AGE", 0);    // default 0
        ((TextView) findViewById(R.id.tvShow)).setText("Hello " + name + ", " + age);
    }
}
// MainActivity.java – button click
Button btn = findViewById(R.id.btnNext);
btn.setOnClickListener(v -> {
    Intent i = new Intent(MainActivity.this, SecondActivity.class);
    i.putExtra("USER_NAME", "Amrit");     // key, value
    i.putExtra("USER_AGE", 19);
    startActivity(i);                      // Second Activity khul gayi
});

  5. Second Activity ke liye exported="false" – sirf apni app khol sakti hai.

Topic 6: Intents 🟢 BTEUP SYLLABUS

🔵 BASIC FOUNDATION

A. Introduction

  • What: Intent ek message/request hai jo Android ko batata hai "mujhe ye kaam karna hai".
  • Why: Components (Activity, Service, Receiver) ek dusre ko direct nahi jaante; Intent unko jodta hai.
  • Where: Activity kholna, service start karna, broadcast bhejna, dusre app ko use karna.

B. Definition

DefinitionAn Intent is a messaging object used to request an action from another app component. It is used to start an Activity, start a Service, and deliver a Broadcast.

C. Hinglish

HinglishIntent = "chitthi / request slip". Tum Android ko slip dete ho: "Is website ko khol do" ya "Is screen par le jao". Android dekhta hai kaun sa component ye kaam kar sakta hai aur wahan bhej deta hai.

Types of Intent 🟢

  • Explicit Intent: Tum naam batate ho kaun sa component chahiye. Jaise: "MainActivity se SecondActivity par jao". (App ke andar.)
  • Implicit Intent: Tum sirf kaam batate ho, component nahi. Jaise: "Ye link kholo". Android khud best app dhundhta hai (Chrome/Browser).

D. Real-Life Examples

  • WhatsApp "Share" button: Implicit Intent – Android sab apps ki list dikhata hai.
  • Phone me number par tap: Dialer khulta hai (implicit).
  • Login ke baad Home screen: Explicit Intent.
  • Google Maps me link: Implicit Intent – Browser ya Maps app.

F. Important Points 🔴

  • Intent ke parts: Component name, Action, Category, Data, Extras, Flags.
  • Explicit = naam diya; Implicit = kaam diya.
  • Data bhejne ke liye putExtra(), lene ke liye getXxxExtra().

Topic 7: Receiving and Broadcasting Intents 🟢 BTEUP SYLLABUS

🔵 BASIC FOUNDATION

A. Introduction

  • What: Broadcast = sabko ek saath announcement. Jo app sunna chahe wo Broadcast Receiver se sun leti hai.
  • Why: System ya app me koi event ho (battery low, internet gaya, phone restart) to interested apps ko pata chale.
  • Where: Battery alert, airplane mode, boot complete, SMS, custom app events.

B. Definitions

BroadcastA Broadcast is a system-wide or app-wide message that announces that some event has happened.
Broadcast IntentA Broadcast Intent is an Intent object that carries the broadcast message and is sent using sendBroadcast().
Broadcast ReceiverA Broadcast Receiver is an Android component that listens for and responds to broadcast Intents.

C. Hinglish

HinglishRailway station par announcement hota hai: "Train 5 minute late". Jo yatri sunna chahta hai wo sunta hai. Yahan announcement = Broadcast Intent, announcer = system ya app, aur sunne wala yatri = Broadcast Receiver.

D. Real-Life Examples

  • Battery low: System broadcast bhejta hai, power-saver app sunkar action leti hai.
  • Airplane mode on: WhatsApp/Chrome ko pata chalta hai ki internet band.
  • Phone restart: BOOT_COMPLETED broadcast sunkar alarm/reminder app phir se schedule karti hai.
  • Custom: Download complete hone par app apna broadcast bhejti hai.

F. Important Points 🔴

  • Broadcast Receiver ≠ Service: Receiver sirf chhota reaction deta hai (onReceive ~10 sec), lambi cheez Service/WorkManager.
  • Receiver ki UI nahi hoti.
  • Do tarah: Static (manifest) aur Dynamic (code me register).

// MyReceiver.java
public class MyReceiver extends BroadcastReceiver {
    @Override
    public void onReceive(Context context, Intent intent) {          // 1
        String action = intent.getAction();
        if ("com.example.MY_EVENT".equals(action)) {                   // 2
            String msg = intent.getStringExtra("msg");
            Toast.makeText(context, "Received: " + msg, Toast.LENGTH_SHORT).show(); // 3
        } else if (Intent.ACTION_AIRPLANE_MODE_CHANGED.equals(action)) {
            Toast.makeText(context, "Airplane mode changed", Toast.LENGTH_SHORT).show();
        }
    }
}
// MainActivity.java
public class MainActivity extends AppCompatActivity {
    private final MyReceiver receiver = new MyReceiver();

    @Override protected void onStart() {
        super.onStart();
        IntentFilter filter = new IntentFilter();
        filter.addAction("com.example.MY_EVENT");
        filter.addAction(Intent.ACTION_AIRPLANE_MODE_CHANGED);
        ContextCompat.registerReceiver(this, receiver, filter,
                ContextCompat.RECEIVER_NOT_EXPORTED);                   // 4
    }
    @Override protected void onStop() {
        super.onStop();
        unregisterReceiver(receiver);                                   // 5
    }
    public void sendMyBroadcast(View v) {
        Intent i = new Intent("com.example.MY_EVENT");
        i.putExtra("msg", "Hello Broadcast");
        i.setPackage(getPackageName());                                 // 6
        sendBroadcast(i);                                               // 7
    }
}
  1. onReceive broadcast aane par chalta hai.
  2. Action string se pehchante hain kaun sa broadcast aaya.
  3. Toast se output dikhaya.
  4. Receiver register kiya. RECEIVER_NOT_EXPORTED = sirf apni app ke broadcast (Android 13/14 me flag dena zaroori).
  5. Stop par unregister – memory leak na ho (start/stop ya resume/pause ka pair rakho).
  6. setPackage broadcast ko apni app tak hi rakhta hai (security).
  7. Broadcast bheja. Output: Toast "Received: Hello Broadcast".

Types & Lifecycle

  • System broadcasts: ACTION_BOOT_COMPLETED, ACTION_AIRPLANE_MODE_CHANGED, ACTION_BATTERY_LOW, ACTION_TIMEZONE_CHANGED.
  • Custom broadcasts: apni action string, jaise com.example.MY_EVENT.
  • Normal (sendBroadcast, sabko ek saath) vs Ordered (sendOrderedBroadcast, priority ke hisab se ek-ek).
  • Lifecycle: BroadcastReceiver ka sirf ek method hai – onReceive(). Uske return hote hi receiver object "inactive" ho jata hai. Ye main thread par chalta hai aur ~10 second me khatam hona chahiye.
Real-life flow

🟡 ADVANCED KNOWLEDGE

Modern Android Restrictions on Broadcasts

  • Android 7+: CONNECTIVITY_ACTION manifest me nahi; aur ab deprecated – ConnectivityManager.NetworkCallback use karo.
  • Android 8.0+: Zyadatar implicit broadcasts manifest receiver se receive nahi hote (exceptions: BOOT_COMPLETED, LOCALE_CHANGED, etc.). Alternative: context-registered receiver, explicit broadcast, ya WorkManager/JobScheduler.
  • Android 13/14: Context-registered receiver ke liye RECEIVER_EXPORTED ya RECEIVER_NOT_EXPORTED flag dena padta hai (Android 14 targets ke liye zaroori).
  • Android 12+: Intent filter wale receiver par android:exported likhna zaroori.
  • Deprecated: LocalBroadcastManager → LiveData / Flow / callbacks.

Security Considerations

  • Custom broadcast se sensitive data mat bhejo – koi bhi receiver sun sakta hai.
  • setPackage() ya RECEIVER_NOT_EXPORTED se limit karo.
  • Receiver ko permission se protect karo: sendBroadcast(intent, "com.example.PERMISSION").
  • onReceive me aaye Intent ko hamesha validate karo (null/action check).
  • Lambi kaam ke liye goAsync() + thread, ya WorkManager/Service start karo.
Common errors
  • IntentReceiverLeaked – register kiya par unregister nahi kiya.
  • IllegalArgumentException: Receiver not registered – unregister do baar ya bina register ke.
  • Android 8+ par manifest se implicit broadcast na milna.

    private final ActivityResultLauncher<String> cameraPermLauncher =
        registerForActivityResult(new ActivityResultContracts.RequestPermission(),
            isGranted -> {
                if (isGranted) {
                    openCamera();                       // Allow
                } else {
                    Toast.makeText(this, "Camera permission denied", Toast.LENGTH_SHORT).show(); // Deny
                }
            });

    @Override protected void onCreate(Bundle b) {
        super.onCreate(b);
        setContentView(R.layout.activity_main);
        findViewById(R.id.btnCamera).setOnClickListener(v -> checkAndRequestCamera());
    }

    private void checkAndRequestCamera() {
        if (ContextCompat.checkSelfPermission(this, Manifest.permission.CAMERA)
                == PackageManager.PERMISSION_GRANTED) {          // 2) pehle se mili?
            openCamera();
        } else if (shouldShowRequestPermissionRationale(Manifest.permission.CAMERA)) {
            new AlertDialog.Builder(this)                         // 3) kaaran batao
                .setMessage("Photo lene ke liye camera permission chahiye")
                .setPositiveButton("OK", (d, w) -> cameraPermLauncher.launch(Manifest.permission.CAMERA))
                .setNegativeButton("Cancel", null).show();
        } else {
            cameraPermLauncher.launch(Manifest.permission.CAMERA); // 4) system popup
        }
    }
    private void openCamera() { Toast.makeText(this, "Camera ready", Toast.LENGTH_SHORT).show(); }
}

  3. shouldShowRequestPermissionRationale true ho to user ne pehle deny kiya tha; kaaran samjhana achha practice.
  4. launch() system ka permission dialog dikhata hai. Output: Allow par "Camera ready"; Deny par "Camera permission denied".

6. Common Mistakes to Avoid

  • ❌ Lifecycle order galat likhna (onRestart sirf Stop ke baad aata hai).
